## 项目简介

MoonBit 生态里**已经有纯 MoonBit 的线性代数包**（如 [Luna-Flow/linear-algebra](https://github.com/Luna-Flow/linear-algebra)、[moonbit-community/linalg](https://github.com/moonbit-community/linalg)），但**没有把成熟原生数值栈接进来的绑定**：`moonbitlang/core` 没有矩阵库；mooncakes.io 上检索不到 Eigen / Armadillo / BLAS / LAPACK 的任何绑定；已有实现是纯 MoonBit 重写，而非对接经过长期验证的原生数值栈。

两者是**互补而非替代**关系：纯 MoonBit 实现可控、可读、可跨后端；绑定则直接复用几十年验证过的算法与优化。本项目补上的是后一条路径，其产物原则上可以作为前者的原生后端。

moonbit-eigen 把 C++ 生态中经过十几年验证的 header-only 线性代数库 **Eigen** 接入 MoonBit，为需要在 MoonBit 中做矩阵运算与线性求解的库作者、工具开发者和应用开发者提供可复用的基础能力。

数值算法的难点不在"把公式写出来"，而在**数值稳定性、边界条件与浮点误差控制** —— 这些是几十年踩坑积累的结果，重新实现一遍代价极高。因此本项目选择**绑定而不是重写**：把 Eigen 当作后端，用一层刻意保持很薄的 C++ 胶水处理 MoonBit 做不到的事（模板实例化、ABI 归一化、生命周期桥接）；而错误处理、维度检查、格式化输出、示例与测试**全部由 MoonBit 承担**，使这个绑定真正是"MoonBit 的库"而不是"Eigen 的转写"。

项目已在 Windows + MSVC 上完整跑通：类型检查 0 errors、**38 个测试全绿**、三个示例输出正确、ASan 实测生效、CI 双平台通过。

## 核心功能范围

**MoonBit 公开 API**

- 提供 MoonBit 原生的 `Matrix` 类型与公开方法；**所有可能失败的操作返回 `Result[T, String]`**，不抛异常，跨语言边界的问题不会静默变成崩溃；
- 构造：`zeros(rows, cols)`、`from_array(rows, cols, data)`（行主序，要求元素个数匹配）；
- 访问：`rows()`、`cols()`、`get(i, j)`、`set(i, j, v)`、`to_array()`；
- 运算：`add` / `sub`（要求同尺寸）、`mul`（矩阵乘法，要求左列数 = 右行数）、`scale(k)`、`transpose()`；
- 线性代数：`solve(b)`（解 `Ax = b`，要求方阵，**奇异矩阵返回明确错误**）、`dot(other)`、`norm()`（Frobenius）、`det()`；
- 格式化：`to_string()` —— 纯 MoonBit 实现的列对齐多行渲染，并按 1e6 抹掉浮点显示噪声（`0.7999999999999999` → `0.8`）。

**C++ 胶水层（刻意保持薄）**

- 把 Eigen 的模板实例化掉，边界上只暴露具体的 `MatrixXd` 运算；
- **ABI 归一化**：Eigen 默认列主序，所有跨边界搬运按 `(i, j)` 逐元素进行，对外统一行主序，不让隐含约定泄漏；
- 生命周期：`moonbit_make_external_object` 注册 finalizer，GC 回收时自动释放；
- 异常拦截：胶水层全量 `try/catch`，把 C++ 异常转成"错误哨兵 + 错误信息"，**绝不让异常跨越 ABI 边界**；
- 失败时返回 `valid = false` 的哨兵对象（可安全回收），而不是 `nullptr`；
- 错误信息以 UTF-8 字节跨边界（`moonbit_make_bytes` + MoonBit 侧 `@utf8.decode_lossy`），中文提示不乱码。

**验证与工程质量**

- `selftest/` 包：**零第三方依赖**的 FFI 机制自检 —— 外部对象 + finalizer、`#borrow` 传参、错误哨兵约定、UTF-8 编码往返、500 对象 GC 压力；它让"MoonBit 能不能调用 C++"这个机制问题可以**独立于 Eigen 得出结论**；
- `reference/` 包：一份**零第三方依赖的纯 MoonBit 线性代数参考实现**（含手写的高斯消元 + 部分主元），作为绑定的**独立对拍对象**；它同时是"MoonBit 足以表达数值算法"的具体证据；
- **5 组跨语言对拍**（`examples/crosscheck`）：矩阵乘法、2×2 与 3×3 解方程、行列式、奇异矩阵判定；实测矩阵乘法误差 `0`，**解方程与独立实现吻合到 2.2e-16**，奇异矩阵两边都正确拒绝；
- **38 个 MoonBit 测试**（`src` 18 + `reference` 13 + `selftest` 7），持续保持全绿；其中包含错误路径测试，以及参考实现自己的**手算期望值**测试（含"必须换行才能解"与"换行必须翻符号"这类专门盯实现缺陷的用例）；
- **AddressSanitizer 接入**（Windows / MSVC），并内置**三道防"假绿"断言**：目标字段必须存在 → 注入必须真的改到文件 → 产物里必须真的出现 ASan 符号；
- **CI 双平台**：Windows 跑完整测试与示例，Linux 跑纯类型检查；
- **一键复现**：`scripts/demo.ps1`（`scripts/spike.ps1` 为兼容旧名的薄壳）8 个步骤全过，输出与日志落在 `demo/out/`；
- 三个可运行示例：`examples/solve`（解方程 + 错误路径）、`examples/linreg`（一元线性回归，精确复原截距 1 / 斜率 2）、`examples/crosscheck`（对拍）。

## 移植或参考说明

- **原项目名称**：Eigen（C++ header-only 线性代数模板库）
- **原项目链接**：<https://gitlab.com/libeigen/eigen>
- **原项目许可证**：**MPL2**（部分文件为 MPL2 / LGPL3+ 双许可），Copyright (c) Eigen authors
- **本项目许可证**：**MIT**（见仓库 `LICENSE`）

**本项目不复制 Eigen 源码入库**：由 `scripts/fetch-eigen.ps1` 按固定版本从上游获取（三条路径：GitLab 官方 tag → GitHub 镜像 → GitHub 指定 commit 归档），成功后校验关键文件存在、**解析并打印真实版本号**，并写入 `src/third_party/eigen/SOURCE.txt` 作为可复现凭证。

与原项目相比，本项目做了以下简化和重新设计：

- **把 Eigen 当后端，不重写任何数值算法**。C++ 侧只做 MoonBit 做不到的事（模板实例化、ABI 归一化、生命周期桥接），刻意保持很薄；错误处理、维度检查、格式化、示例、测试全部在 MoonBit 侧完成，以满足"以 MoonBit 作为项目主要实现语言"的验收要求。实测实现代码构成：MoonBit 1645 行（70%）/ C++ 716 行（30%）。
- **不做模板化**。Eigen 的标量类型与维度都是模板参数，而**模板无法跨越 C ABI**；本绑定只暴露 `f64` 与运行期维度，模板只在胶水层内部被实例化掉。
- **对外统一行主序**。Eigen 的 `MatrixXd` 默认列主序，与 MoonBit 数组的直觉不符；所有跨边界搬运按 `(i, j)` 逐元素进行，不让存储布局这种"不会报错、只会算错"的隐含约定泄漏给用户。
- **用 `Result[T, String]` 取代异常与断言**。Eigen 的断言是 `abort()` 而非可捕获的异常 —— 跨 FFI 边界会直接终止宿主进程（实测退出码 `0xc0000409`）。因此所有前置条件都在 MoonBit 侧或胶水层显式检查。
- **不做 Java/C++ 式的工程结构复刻**，改用 MoonBit 原生包结构、类型系统与测试方式组织代码（`src` / `reference` / `selftest` / `examples` 四个包，各自独立可测）。
- **v1 明确不做的范围**（README 的 Limitations 一节有完整列表）：稀疏矩阵、复数类型、特征值 / SVD / QR 分解、显式 SIMD 控制、回调式迭代（跨 C ABI 传闭包风险高）、多线程并行（Eigen 需要 OpenMP 编译选项）。
- **版本如实说明**：本项目实测获取到的是 **Eigen 3.3.90**（GitHub 镜像 master 的版本号，即 3.4 正式发布前的开发版本号），**不是 3.4.0 正式版**。原因与取舍见 README 的「来源与许可」一节；所用 API 在 3.3 系列均已存在。
