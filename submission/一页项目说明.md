## 1. 解决什么问题

**MoonBit 目前没有任何线性代数能力。**

- `moonbitlang/core` 里没有矩阵库；
- mooncakes.io 上检索不到 Eigen / Armadillo / BLAS / LAPACK 的**任何**绑定；
- 现有数值相关包是纯 MoonBit 重写（如 NumPy 移植），而非对接经过验证的 C++ 数值栈。

数值算法是几十年踩坑积累的产物，**重复造轮子在数值领域尤其昂贵**（数值稳定性、
边界条件、浮点误差控制）。本项目的思路是：把 C++ 生态中经过长期验证的
header-only 线性代数库 **Eigen** 接入 MoonBit，让 MoonBit 开发者直接获得
矩阵运算与线性求解能力。

## 2. 技术路线

```
MoonBit 代码  ──extern "C"──▶  胶水层 (eigen_shim.cpp)  ──▶  Eigen (header-only)
                              · 模板实例化
                              · ABI 归一化（行主序）
                              · 生命周期与异常拦截
```

**关键难点及对策**（这几点是本项目的技术含量所在）：

| 难点 | 对策 |
|---|---|
| Eigen 是重度模板库，**模板无法跨越 C ABI** | 在 C++ 侧把模板实例化掉，边界上只暴露具体的 `MatrixXd` 运算 |
| MoonBit 的 `String` 是 GC 管理的 UTF-16 对象，不能直接当 `char*` | 本项目边界上**只有 `double*` 与 `int32_t`**；错误信息用官方推荐的 `moonbit_make_bytes` + MoonBit 侧 `@utf8.decode_lossy` |
| C++ 对象生命周期 vs MoonBit 引用计数 | `moonbit_make_external_object` 注册 finalizer，GC 回收时自动 `delete` |
| C++ 异常跨越 ABI 边界是未定义行为 | 胶水层全量 try/catch，转成"错误哨兵 + 错误信息"，MoonBit 侧映射为 `Result[T, String]` |
| Eigen 默认列主序，与 MoonBit 数组直觉不符 | 所有搬运按 `(i, j)` 逐元素进行，对外统一行主序，不让隐含约定泄漏 |
| 抽象类型没有 null 语义，返回 `nullptr` 会产出垃圾句柄 | 失败时返回 `valid=false` 的哨兵对象（可安全回收），用 `rows() == -1` 识别 |

## 3. 交付物

| 验收要求 | 交付 |
|---|---|
| 代码 | MoonBit API 层 + FFI 声明层 + C++ 胶水层 |
| README | 快速上手 + 架构图 + API + **Limitations** + **来源与许可** |
| 测试 | 17 个单元测试（含 5 个错误路径测试）+ ASan/UBSan + CI |
| 可运行示例 | `examples/solve`、`examples/linreg`、`examples/bench` |
| 可复现演示 | `scripts/demo.ps1` / `scripts/demo.sh` 一键脚本（输出与日志落在 `demo/out/`）+ 终端录屏 |
| **附加（对社区最有复用价值）** | `docs/TYPE_MAP.md`（MoonBit ↔ C++ 类型与内存映射表）、`docs/PITFALLS.md`（踩坑记录与已知 issue 清单） |

**关于"MoonBit 为主要实现语言"**：C++ 侧刻意保持薄，只做 MoonBit 无法完成的事
（模板实例化、ABI 归一化、生命周期桥接）；错误处理、维度检查、格式化输出、
示例、测试全部由 MoonBit 承担。`docs/TYPE_MAP.md` 与 `docs/PITFALLS.md`
是纯 MoonBit 生态资产，其中踩坑记录对后续所有想写 C++ 绑定的人都有直接价值。
